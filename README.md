# 부름차: 면허 반납 고령자의 이동 공백을 메우는 생활권 DRT 설계 (금천구 시흥동)

이 저장소는 분석보고서의 세부 근거 자료이다. 보고서의 방법·가정·결과 숫자는 아래 두 문서에 근거를 둔다.

- [방법론과 결과 (docs/methodology.md)](docs/methodology.md): 분석 절차, 가정, 결과표, 한계
- [숫자 출처표 (docs/숫자출처표.md)](docs/숫자출처표.md): 주요 숫자별 스크립트와 출력 파일

## 프로젝트 개요
서울 행정동 단위로 고령층의 차량 의존 행태와 대중교통 접근성을 분석해 이동 취약지대를 찾고(1단계), 금천구 시흥동 생활권(시흥3·4·5동 승차, 시흥1동 목적지 허브)에서 70세 이상 운전면허 자진반납자를 위한 수요응답형 교통(DRT)을 설계하였다. 보행 400m 기준 최대커버링입지모델(MCLP)로 승차 정류소 13곳을 정하였다. 반납자 수요(하루 24~276명) 시나리오별 실시간 배차 시뮬레이션으로 필요 차량 대수와 단계별 전환 기준을 구하였다. 같은 승객을 태운 고정노선과의 비교, 반납 후 자가용 계속 이용 대비 탄소 배출, DRT 도입 전후 대중교통 접근성 지수 변화도 계산하였다. 방법론과 진행 상황의 기준 문서는 `docs/methodology.md`이다.

## 폴더 구조
```
├─ README.md, requirements.txt, .env.example, .gitignore
├─ docs/
│   ├─ methodology.md        방법론·결과·한계의 기준 문서
│   └─ 숫자출처표.md          주요 결과 숫자의 스크립트·출력 파일 대응표
├─ scripts/                  최종 스크립트(아래 실행 순서)와 1단계 스크립트
│   └─ _archive/             이전 버전·보조(미사용) 스크립트(실행 불필요, 보관용)
├─ outputs/                  결과 표(csv)·그림(png)
│   └─ _archive/             기준이 바뀌어 대체된 이전 결과
└─ data/
    ├─ raw/                  원자료(커밋 제외, 아래 데이터 출처 참고)
    ├─ interim/              중간 산출물·시뮬레이션 체크포인트(커밋 제외)
    └─ verified/             1단계 검증 결과(서울 반납률·접근성 지수 v3 등)
```

## 실행 순서 (프로젝트 루트에서 `python scripts/<파일>`)
1. 1단계(서울 행정동): 결과는 `data/interim/재현확인/`에 저장한다. 기준 결과 `data/verified/`는 덮어쓰지 않는다.
   - `step2_license_holders.py` → `step3_parse_pdf.py` → `step4_rate.py` (자치구 반납률)
   - `build_admdong_crosswalk.py` (행정동 코드 매핑)
   - `home_arrival_hour_distribution.py` (귀가 도착 시간대)
   - `homebound_elderly_mode_share.py` → `homebound_purpose_crosscheck.py` → `income_households_merge.py` (귀가 시간대 수단·우선순위·귀가 비중·소득)
   - `elderly_population.py` (65세 이상 인구)
   - `accessibility_metrics.py` → `accessibility_index.py` → `accessibility_sensitivity.py` (접근성 원지표·지수 v1·가중치 민감도)
   - `build_final_table.py` → `accessibility_index_v3.py` → `update_final_table_v3.py` (최종표·접근성 지수 v3)
   - `gu_correlation_recheck.py` (구 단위 상관)
2. `금천구_목적지후보.py`: 시설 지오코딩. `data/interim/geocode_cache.json`이 있으면 API를 다시 부르지 않는다.
3. `금천구_MCLP.py` → `금천구_MCLP_v3.py` → `금천구_MCLP_v4.py` (공통 모듈 `mclp_common.py`, `osm_roads.py`)
4. `금천구_OD검증.py`
5. `금천구_DRT_v3_준비.py` → `금천구_DRT_v4_준비.py` → `금천구_DRT_v4_시뮬.py`
6. `금천구_반납자수요.py` → `금천구_DRT_반납자시뮬.py`
7. `금천구_시흥1동도착_검증.py` → `금천구_DRT_반납자_그림.py`
8. `금천구_탄소계산.py` → `금천구_DRT_검토보완.py` → `금천구_DRT_검토2.py` → `금천구_탄소검토.py` (단계표 대수 기준 탄소, 전비 3.9 기본) → `금천구_동시탑승점검.py` (동시 탑승 최대 인원). 마지막 두 스크립트는 반납자 시뮬·검토2 체크포인트를 읽는다.
9. `금천구_접근성_DRT전후.py`
10. 보고서 그림(저장된 결과만 읽고 분석은 다시 하지 않는다): `그림_보고서.py` (그림 1 자치구 산점도, 그림 2 정류소 지도, 그림 3 필요 차량) → `그림_노선지도.py` (노선 지도: 고정노선 vs DRT)
- `금천구_DRT_v4_그림.py`는 이전 노선 지도와 시간대별 호출 그림을 만든다. 보고서 그림은 10번에서 만든다.
- `금천구_핀포인트.py`는 금천구 10개 동 핀포인트 분석으로, 따로 실행한다.
- 시뮬레이션은 시나리오별 체크포인트를 `data/interim/*_runs/`에 저장하고, 다시 실행하면 완료된 시나리오를 건너뛴다. 난수는 고정 시드(20261011)를 써서 같은 결과가 재현된다.

### 스크립트 참고
- 입력 생성용 스크립트 3개: `금천구_MCLP.py`, `금천구_MCLP_v3.py`, `금천구_DRT_v3_준비.py`는 이전 버전이지만 최종 스크립트가 읽는 파일을 만든다(`data/interim/MCLP_시설_중복제거.csv`, `outputs/MCLP_후보정류소.csv`, `outputs/MCLP_고정목적지정류소.csv`, `outputs/MCLP_v3_수요점_100m보정.csv`, `data/interim/DRT_v3_입력.pkl`). 처음부터 재현하려면 실행 순서대로 함께 돌려야 하므로 `scripts/`에 두었다.
- 1단계 스크립트: 서울 반납률, 행정동 코드 매핑, 차량 의존 우선순위, 소득, 고령인구, 접근성 지수를 만든다. 입력은 `data/raw/` 기준 상대경로이고, 결과는 `data/interim/재현확인/`에 저장된다. 이 폴더에서 처음부터 실행한 결과가 `data/verified/`의 기준 결과 9개와 모두 같았다(최대 차이 0, 2026-10-13). `update_final_table_v3.py`가 읽는 `data/raw/접근성_9곳_v3_구성요소.csv`는 원 프로젝트에서 `accessibility_index_v3.py`의 화면 출력을 저장한 파일이다. 만드는 스크립트가 없어 입력으로 두었다(값은 재현 v3와 일치).
- `금천구_DRT_v4_그림.py`는 `data/interim/DRT_v4_민감도_결과.pkl`(1% 시간대 그림)을, `금천구_DRT_v4_시뮬.py`는 `outputs/DRT_v3_필요차량수.csv`(비교 출력)를 읽는다. 두 파일은 `scripts/_archive/`의 이전 스크립트가 만들었으므로, 처음부터 다시 만들려면 해당 보관 스크립트가 필요하다.

## 재현 방법
1. Python 3.11에서 `pip install -r requirements.txt`를 실행한다.
2. `data/raw/`에 아래 원자료를 넣는다.
   - 원자료는 하위 폴더 없이 `data/raw/`에 바로 둔다(아래 표의 파일명 그대로, zip은 풀지 않음).
   - 자진반납 PDF(22년~25년 자진반납.pdf)는 경찰청 정보공개청구로 받은 자료라 공개 배포하지 않는다.
3. 시설 좌표를 새로 지오코딩할 때만 `.env.example`을 `.env`로 복사하고 `KAKAO_REST_API_KEY=<카카오 REST API 키>`를 채운다. `.env`는 `.gitignore`로 커밋에서 제외된다. 지오코딩 캐시가 있으면 키 없이 실행된다.
4. 실행 순서대로 스크립트를 돌린다.
- 주요 결과 숫자의 스크립트·출력 파일은 `docs/숫자출처표.md`에 정리하였다.
